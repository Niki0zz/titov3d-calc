# TitoV3D Calc — веб-версия (Windows + Android)

Порт вашего Tkinter-приложения **TitoV3D Calculator v3.9** на HTML/JS.
Один файл `index.html`, никаких установок, Python и прав администратора не нужны.
Работает в Windows, на Android, а также на macOS/Linux.

**Текущая версия: 6.0** (Windows + Android сборки).
Что изменилось после аудита логики и защиты — см. [`REVIEW.md`](REVIEW.md).
Методика коэффициентов — [`FILAMENTS.md`](FILAMENTS.md).
Сборка и установка — [`BUILD.md`](BUILD.md), отчёт о тестах — [`REPORT.md`](REPORT.md).

Формулы не менялись:

```
материал      = г × (цена_катушки / (вес_катушки × 1000))
электричество = Вт/1000 × часы_печати × тариф
амортизация   = (цена_принтера / ресурс_ч) × часы_печати
работа        = моделирование + оператор(всё время печати) + постобработка
база          = материал + электричество + амортизация + работа
сложность     = (материал + электричество) × (коэф_сложности − 1)
накладные     = (база + сложность) × коэф_накладных
себестоимость = база + сложность + накладные + доставка
цена          = себестоимость × (1 + наценка% / 100)
маржа         = (цена − себестоимость) / цена × 100
```

## Что нового в 6.0

1. **Собраны приложения:** Windows (`.exe`, `.msi`, установщик NSIS) и Android
   (подписанный `.apk`). Файлы — в папке `Сборки`.
2. **Определение платформы** внутри приложения: в «Настройках» видно
   «Платформа: Windows / Android / браузер».
3. **Экспорт на Android** работает через системное «Поделиться» (в WebView обычное
   скачивание файла не работает). Если плагин недоступен — открывается окно
   с текстом файла и кнопкой «Скопировать», данные не теряются.
4. Версия 6.0.0, `versionCode` 600, `minSdk` 24 (Android 7.0+).

## Что нового в 5.1

1. **Принтеры по умолчанию:** `Creality_K1C` (350 Вт, 45 000 ₽) и
   `BambuLab_P2S` (200 Вт — паспортное потребление в режиме PLA, 65 000 ₽).
   Старые K1 / K1 Max / Ender 3 удаляются при обновлении, если на них нет
   заказов в истории; принтеры с историей сохраняются, чтобы не порвать записи.
2. **Исправлено двойное списание ресурса:** повторное сохранение теперь
   блокируется по физическим параметрам печати (принтер, филамент, вес, время).
   Изменение наценки или доставки кнопку не разблокирует — иначе одну и ту же
   печать можно было записать дважды.
3. **Импорт дополняет базу** материалами каталога и стандартными принтерами,
   а диалог заранее показывает, сколько записей добавится.
4. **Защита от потери данных при миграции принтеров:** принтер, на который
   ссылается история, никогда не удаляется автоматически.

## Что нового в 5.0

1. **Блок наценки.** Поле «Наценка, %» и живая подсказка маржи. В карточке
   результата — себестоимость, сумма наценки и цена продажи; в истории хранятся
   и себестоимость, и цена.
2. **Каталог из 40 FDM-материалов** с ориентировочными ценами и коэффициентами
   сложности. Точка отсчёта — **PLA = 1.50**. Полная таблица и методика:
   [`FILAMENTS.md`](FILAMENTS.md).
3. **Миграция.** При первом запуске старой базы в неё добавляются недостающие
   материалы, а дефолтные коэффициенты PLA/PETG/ABS (1.0 / 1.05 / 1.2)
   переводятся на новую шкалу (1.50 / 1.87 / 2.45). Ваши цены и
   переименованные материалы не трогаются.
4. **Поиск и группировка** материалов: «Базовые», «Инженерные», «Гибкие»,
   «Поддержки», «Высокотемпературные».

## Отличия от десктопной версии

1. **Хранение.** Вместо файла в `C:\Program Files\TitoV3DCALC` данные лежат в
   localStorage браузера. Никаких `data_path.flag` и `PermissionError` — прав
   администратора не требуется.
2. **Резервная копия.** Меню «⋯» → «Экспорт данных» скачивает
   `3d_calc_data_v2.json` ровно в формате Python-версии. Импорт на другом
   устройстве восстанавливает всё: принтеры, филаменты, настройки, историю.
3. **Дополнительно:** экспорт истории в CSV, печать/PDF текущего расчёта,
   автосохранение при каждом изменении, адаптивный интерфейс под телефон.
4. Убрано устаревшее поле `remaining_resource` — при импорте старого JSON оно
   просто игнорируется, остаток считается динамически, как и в вашей v3.9.

## Быстрый старт

### Windows
Двойной клик по `index.html` или по `Открыть калькулятор.bat`.

### Android
1. Отправить `index.html` себе в Telegram «Избранное» / на Google Drive / по кабелю.
2. Открыть файл через файловый менеджер → «Открыть с помощью» → Chrome.
3. Chrome → меню ⋮ → «Добавить на главный экран». Дальше — как приложение.

### Перенос данных из Python-версии
1. Возьмите `3d_calc_data_v2.json` из `C:\Program Files\TitoV3DCALC\`
   (или из `C:\Users\<вы>\TitoV3DCALC_Config\`).
2. В веб-версии: меню «⋯» → «Импорт данных» → выберите этот файл.
3. Обратно: «Экспорт данных» и подмените файл на десктопе.

## Ограничения

- Нет автоматической записи в файл на диск (браузер этого не умеет) — для бэкапа
  используйте экспорт JSON. localStorage может очиститься при очистке данных сайта.
- Это не «настоящий» .exe/.apk, а веб-приложение. Для установки иконкой на
  Android используется «Добавить на главный экран».

## Защита и проверки (v4.1)

- Все числа ограничены разумными диапазонами; отрицательные и «бесконечные» значения
  не ломают расчёт и подсвечивают поле.
- Деление на ноль (вес катушки, ресурс, цена) даёт 0 с понятным предупреждением,
  а не `∞`.
- Повторное сохранение одного и того же расчёта блокируется — ресурс не спишется дважды.
- Импорт JSON защищён от загрязнения прототипа (`__proto__`, `constructor`),
  ограничен 5 МБ и проверяется на структуру.
- Перед импортом и сбросом автоматически создаётся резервная копия —
  меню «⋯» → «Восстановить предыдущие данные».
- CSV экранирует формулы (`=`, `+`, `-`, `@`), чтобы имена не исполнялись в Excel.
- Имена уникальны без учёта регистра; замена существующего требует подтверждения.


## Если нужны настоящие .exe и .apk

На машине нет Flutter и Android SDK, поэтому сборка не выполнялась. Варианты:

- **.exe** — Tauri или Electron вокруг этого же `index.html` (нужен Rust/Node).
- **.apk** — обёртка WebView (Capacitor / Android Studio, нужен Android SDK,
  ~3–4 ГБ загрузок).
- **Гибрид как у вас** — оставить Tkinter для Windows и эту веб-версию для Android,
  синхронизируя через JSON.

Скажите, какой путь предпочтителен — соберу.
