# MCP-сервер TitoV3D Calc

Даёт ИИ-агенту (мне) доступ к калькулятору: считать, смотреть принтеры и материалы,
записывать заказы в историю — теми же формулами и по тем же данным, что в приложении.

## Зачем отдельный сервер

Приложение — это HTML в WebView, оно не может само поднять MCP-сервер (браузерная
песочница, нет доступа к процессам). Поэтому MCP-сервер — отдельный процесс Node.js,
который работает с общим JSON-файлом:

```
┌────────────────────┐        ┌──────────────────────┐
│  TitoV3D Calc      │        │  ИИ-агент (OpenCode) │
│  Windows / Android │        │                      │
└─────────┬──────────┘        └──────────┬───────────┘
          │ экспорт/импорт               │ MCP (stdio)
          ▼                              ▼
   data\3d_calc_data_v2.json  ◄──── mcp-server/server.js
```

Файл данных: `%APPDATA%\com.tito.v3dcalc\3d_calc_data_v2.json` — тот же, что читает и
пишет настольное приложение с версии 6.1. Переопределяется переменной `TITO_DATA`.

## Инструменты (12)

| Инструмент | Что делает |
|---|---|
| `app_info` | версия, путь к данным, количество принтеров/материалов/записей |
| `list_printers` | принтеры: мощность, цена, ресурс, израсходовано, остаток |
| `list_filaments` | материалы с ценой за кг, ₽/г и коэффициентом сложности; фильтры `query`, `group` |
| `calculate` | полный расчёт: раскладка, себестоимость, наценка, цена, маржа |
| `save_order` | записать печать в историю (списывает ресурс принтера) |
| `list_history` | последние заказы + суммы по цене и себестоимости |
| `delete_order` | удалить запись, вернуть ресурс |
| `add_printer` | добавить/обновить принтер |
| `add_filament` | добавить/обновить материал |
| `update_settings` | тарифы: электричество, ставки, накладные |
| `export_data` | сохранить JSON для переноса в приложение |
| `import_data` | загрузить JSON, экспортированный из приложения (создаёт `.bak`) |

Параметры `calculate` / `save_order`: `printer`, `filament`, `grams`,
`print_hours` + `print_minutes`, `modeling_*`, `post_*`, `delivery`,
`markup_pct`. Время можно передавать только часами или только минутами.

### Примеры запросов

> Посчитай 120 г PETG на P2S, печать 5 часов, моделирование 30 минут,
> постобработка 20 минут, доставка 350 ₽, наценка 60 %.

> Сколько заработали за последние 20 заказов?

> Запиши этот расчёт в историю.

> Добавь филамент PA6-CF по 6000 ₽ за кг со сложностью 2.7.

## Как это подключено

`~/.config/opencode/opencode.json`:

```jsonc
{
  "mcp": {
    "servers": {
      "tito-calc": {
        "type": "local",
        "command": ["node", "D:\\open code\\mcp-server\\server.js"],
        "cwd": "D:\\open code\\mcp-server"
      }
    }
  }
}
```

Инструменты видны как `tito_calc_calculate`, `tito_calc_list_printers` и т.д.
(в Code Mode — `tools["tito-calc"].calculate(...)`).

Конфиг перечитывается на лету; если сервер не появился — `/reload`.
Проверить: `opencode mcp list` (должно быть `✓ tito-calc connected`).

## Синхронизация с приложением

С версии 6.1 настольное приложение хранит данные в том же файле, что и сервер, —
синхронизация автоматическая:

- приложение читает файл при запуске (файл важнее localStorage);
- любое изменение в приложении (расчёт, заказ, настройки) пишется в файл через 0,4 с;
- сервер читает и пишет тот же файл при каждом вызове.

Поэтому заказ, сохранённый через `save_order`, виден в приложении после его
перезапуска, и наоборот. Путь отображается в приложении: «Настройки» → «Хранение данных».

Для веб-версии и Android файла нет — там обмен по-прежнему через
«⋯» → «Экспорт/Импорт данных» (`import_data` / `export_data`).

## Если нужно поменять данные

Файл можно править вручную или через меня. Перед правкой сервер создаёт `.tmp` и
переименовывает — файл не ломается при сбое. Резервная копия делается при импорте.

## Безопасность

- Сервер работает **только локально**, по stdio, сетевых портов не открывает.
- Данные никуда не отправляются: только чтение/запись локального JSON.
- Входные данные проверяются: диапазоны, имена без `__proto__`/`constructor`,
  лимит 5 МБ на импорт, обязательный `.bak`.
- `save_order` защищён от случайного дубля: одинаковый расчёт за тот же день
  требует явного `allow_duplicate: true`.
- Все изменения идут через тот же `normalize()`, что и в приложении.
